# 개인정보 마스킹

생기부에는 평가에 불필요한 개인정보가 섞여 있다. **Worker가 Anthropic API로 보내기 전에**
1차 정규식 마스킹을 하고, 프롬프트에서도 개인정보 무시를 지시한다(이중 안전장치).
코드 원천: `worker/pii.ts`.

## 마스킹 대상(정규식 1차)

| 종류 | 처리 | 비고 |
|---|---|---|
| 주민등록번호 `######-#######` | `[주민번호]` | |
| 휴대전화 `010-####-####` 등 | `[전화번호]` | 하이픈/공백 변형 포함 |
| 이메일 | `[이메일]` | |
| 생년월일 `YYYY.MM.DD` 류 | 선택적 — 학년/학기 맥락은 보존 | 과도 마스킹 주의 |
| 주소(시/도+구/동 패턴) | `[주소]` | 정확 추출 어려움, 키워드 기반 best-effort |

## 한계와 보완

- **이름**은 정규식만으로 안전 제거가 어렵다(한글 2~4자 어디에나 등장). 완전 제거 대신:
  1) 프롬프트에서 "이름 등 개인 식별정보는 평가에서 무시하라" 명시,
  2) UI 안내: "이름·연락처는 지우고 붙여넣어 주세요" 권장.
- 마스킹은 **무손실 우선**: 평가에 필요한 활동/세특 텍스트를 깎으면 안 된다.
  애매하면 마스킹하지 않고 프롬프트 무시 지시에 맡긴다.

## 운영 시 고려

- 분석 텍스트를 서버에 로그로 남기지 않는다(민감정보).
- 프로덕션에서는 보관/재사용 정책을 명시하고, 가능하면 분석 후 즉시 폐기.
- 참고 서비스(생기부ON)도 "이름·사진·주소 등 불필요한 개인정보 일괄 삭제"를 강조한다.
