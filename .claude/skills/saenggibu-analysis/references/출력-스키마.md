# 출력 JSON 스키마

`submit_saenggibu_analysis` 도구의 `input_schema` 구조. 코드 원천은 `functions/_lib/analysis.ts`의
`ANALYSIS_SCHEMA`, 프론트 타입은 `src/types.ts`의 `AnalysisResult`. 셋을 항상 동기화한다.

## 구조화 출력 제약 (strict: true)

Anthropic structured output 제약을 지킨다:
- 모든 object에 `additionalProperties: false`.
- object의 모든 property는 `required`에 포함(부분 필수 불가).
- 숫자 범위(`minimum`/`maximum`)·문자열 길이 제약은 미지원 → `description`으로 안내.
- 재귀 스키마 금지.

## 필드

```jsonc
{
  "oneLineSummary": "string — 생기부 전체 한 줄 총평",
  "overallScore": "integer — 종합 경쟁력 0~100",
  "scores": [                       // 5개 평가 영역
    { "dimension": "학업역량|전공적합성|발전가능성|인성·공동체|탐구역량",
      "score": "integer 0~100",
      "comment": "string — 생기부 근거 인용 코멘트" }
  ],
  "strengths":  [ { "title": "string", "detail": "string" } ],
  "improvements": [ { "title": "string", "detail": "string", "action": "string(실행 제안)" } ],
  "recommendedMajors": [ { "major": "string", "fitScore": "integer 0~100", "reason": "string" } ],
  "sectionAnalyses": [             // 생기부 항목별 분석
    { "section": "string(예: 교과세특)",
      "summary": "string",
      "keywords": ["string"],
      "strengths": ["string"],
      "improvements": ["string"] }
  ],
  "suggestedActivities": [ { "topic": "string", "rationale": "string", "relatedMajor": "string" } ],
  "interviewQuestions": [ { "question": "string", "intent": "string(출제 의도)" } ]
}
```

## 개수 가이드 (프롬프트로 유도)

- `scores`: 정확히 5개(위 영역).
- `strengths` / `improvements`: 각 3~5개.
- `recommendedMajors`: 3~5개.
- `sectionAnalyses`: 입력에 존재하는 항목만.
- `suggestedActivities`: 3~5개.
- `interviewQuestions`: 4~6개.

스키마 자체는 개수를 강제하지 않으므로(제약 미지원) 프롬프트에서 권장 개수를 안내한다.
