# 분석 프롬프트 설계

`functions/_lib/analysis.ts`의 `SYSTEM_PROMPT`와 사용자 메시지 구성 방식을 설명한다.
실제 문자열은 코드가 원천이며, 여기서는 의도와 구조를 기록한다.

## 시스템 프롬프트의 역할

- **역할 부여**: 대한민국 대입 학생부종합전형 입학사정관/진학지도 전문가.
- **임무**: 입력된 생기부를 평가요소(학업역량/전공적합성/발전가능성/인성·공동체/탐구역량) 기준으로
  진단하고, `submit_saenggibu_analysis` 도구의 스키마에 맞춰 결과를 제출.
- **사실성**: 입력 텍스트에 있는 근거로만 판단. 없는 활동/수상/성적 날조 금지.
- **개인정보**: 이름·연락처·주소·주민번호 등은 평가와 무관하므로 무시(이미 마스킹됨).
- **톤**: 한국어, 구체적·건설적. 보완점은 실행 가능한 다음 행동으로 제시.
- **금지**: 합격/불합격 단정, 특정 대학 합격 확률 보장, 차별적·낙인적 표현.

## 사용자 메시지 구성

```
[지원 희망 계열/전공(선택)]: {targetMajor 또는 "미지정"}
[학년/계열(선택)]: {grade 또는 "미지정"}

다음은 분석할 생활기록부 내용이다(개인정보는 마스킹됨):
"""
{masked 생기부 텍스트}
"""

위 내용을 평가요소 기준으로 분석하고 submit_saenggibu_analysis 도구로 결과를 제출하라.
```

- `targetMajor`가 주어지면 전공적합성 분석과 추천 전공의 기준점으로 사용한다.
  주어지지 않으면 생기부에서 관심 계열을 추론한다.

## 출력 강제

- `tools: [submit_saenggibu_analysis]`, `tool_choice: {type:"tool", name:"submit_saenggibu_analysis"}`,
  도구 `input_schema`에 `strict: true`.
- 강제 tool_choice와 extended thinking은 동시 사용 불가 → `thinking` 미설정(끔).
- `max_tokens`는 16000(비스트리밍 안전 상한). 잘리면(`stop_reason === "max_tokens"`)
  스키마를 더 간결하게 하거나 항목 수 상한을 명시.

## 품질 팁

- 영역 점수의 `comment`에는 **생기부 속 구체 근거**를 인용하게 한다("OO 세특의 ~ 활동" 식).
- 추천 전공 `reason`도 활동 근거에 묶는다. 일반론 금지.
- 면접 질문은 생기부 특정 활동을 캐묻는 형태로(자소서 일반질문 X).
